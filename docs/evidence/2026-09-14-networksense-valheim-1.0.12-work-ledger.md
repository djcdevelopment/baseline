# NetworkSense / Valheim 1.0.12 — extracted work and outcome

Recorded 2026-09-14 PDT. The runtime runs below occurred 2026-09-15 UTC. This is a historical task ledger, not a claim that a test server or client is running now.

## Starting point and boundary

The conversation began in `C:\work\baseline`, the fleet evidence and decision hub. The initial work request was to unblock NetworkSense 0.5.31 on Valheim 1.0.12, where `PortalConnectionCache` bound the old private `m_portalObjects` shape and failed during world load. The proposed repair also covered sector-index and simulation-distance API changes and a missing `Splatform.dll` compile reference. The user's later instructions made OMEN (`wary.fool`) the localhost rendered-client lane, AM4 (`Zephar410`) the Linux second-client/dedicated-server lane, and asked us to inspect installed mods, use the latest build, accept AM4's EULA, and investigate a crash. `lumberjacks-platform` owns the FieldLab harness; `isolate` owns Gateway/container tooling. Product code belongs in those sovereign repositories, not here; see [REPO-MAP](../../REPO-MAP.md).

Evidence labels follow [PD-4](../decisions/pd-4-evidence-standard.md). `VERIFIED` here means a named source revision or retained run output supports the bounded claim. `UNVERIFIED` means its acceptance gate was not exercised. A locally retained candidate or run receipt is historical evidence; neither implies publication or a live deployment.

## What was accomplished

1. **Compatibility code landed — VERIFIED in source.** [`networksense` revision `db5777881b0ab44d0179c056a71d51ed84ce30ae`](https://github.com/djcdevelopment/networksense/commit/db5777881b0ab44d0179c056a71d51ed84ce30ae) replaced the fragile portal-field binding with `GetPortalList()`/sector-keyed `GetPortals()`, patched `AddIfPortal(ZDO, int)`, added `Splatform.dll`, migrated sector users to `Vector2s` and `SimulationDistance.OriginalDistance`, and changed `AddToSector` to use `GetSectorIndex()`. The commit also made other Valheim 1.0.12 compatibility edits beyond the original list. A locally prepared 0.5.80 release-candidate manifest identifies a 947,200-byte DLL, SHA-256 `f65b5c8e20fcf0b5beedd715eb5520f058596cbf88defd2e6b7e1dfce7abc887`, built with the `interim` profile. This is a compiled candidate, not proof of the plan's zero-warning or Inspector gates.
2. **A real two-account runtime smoke completed — VERIFIED for the native path.** After an initial 04:43–05:17 UTC smoke was interrupted by AM4's new EULA, Derek authorized acceptance. The 05:37–06:05 UTC resume used a fresh disposable `NetworkSenseSmoke0915` world and the exact 0.5.80 DLL on the AM4 dedicated server, AM4 client, and OMEN client. AM4's `Questyfour` joined at 05:54:00 UTC; OMEN's `Questy` joined at 05:54:33 UTC. The server recorded both character ZDOIDs and a `region_player_count=2` heartbeat; both clients emitted live FPS, RTT, and network-rate telemetry. The captured point samples are evidence of streaming, not performance benchmarks. A targeted final-client BepInEx scan found zero listed type-initializer, missing-method, type-load, null-reference, Harmony-patch, or BepInEx error matches. The dedicated server loaded the portal cache without its former initializer failure.
3. **The AM4 shutdown crash was narrowed — trigger VERIFIED, root component UNVERIFIED.** An unmodded, post-EULA Valheim client reproduced the native SIGSEGV at address `0x48` and NVIDIA Xid 31 when closed with external X11 `xdotool windowclose`, as the earlier modded client had. In-game Quit exited cleanly in both unmodded and modded runs without a new Xid 31. The operational harness workaround is Log Out then Quit, not external window-close. These observations do not isolate Unity, Steam, the driver, or hardware as the faulting component, and do not establish that NetworkSense caused the crash.
4. **Disposable test state was restored; intentional state changes were recorded.** At teardown both clients and the disposable server were stopped. AM4's original client mods and retained ComfyEra16 server DLL were hash-checked and restored; the disposable world/container and verified clone were removed. OMEN kept the exact NetworkSense plugin, while unrelated mods remained quarantined. AM4's accepted EULA and authorized 1.0.12 Steam update persist. Both selected Steam-cloud characters changed during the authorized joins; after-run snapshots were retained and no older cloud snapshot was automatically written back. This describes the captured teardown, not a current host-state audit.
