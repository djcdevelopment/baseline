Level 1 — the concept

A creature is a state machine; the fields are knobs on its transitions

Every hostile creature carries MonsterAI (behavior) on top of Humanoid/Character (body and stats). The AI moves between a handful of states — sleeping, calm, alerted, engaged, fleeing — and nearly every one of its 79 fields tunes either a state or the trigger that leaves it.

That's why custom fields are the perfect prank toolkit: you're not scripting new behavior, you're re-tuning the transitions vanilla already has — deaf guards, cowardly trolls, greylings that never wake up.

The prank recipes are just transition edits: m_hearRange = 0 is a deaf sentry, m_fleeIfLowHealth = 1.0 is a total coward, m_wakeupRange = 0.5 sleeps until you're standing on it. Vanilla logic, your numbers.

The three ZDO fields

keytypewhat it holds
sleepingboolThe live sleep state — read in Awake, written by Wakeup and Sleep. This is why a sleeping troll stays asleep across save/load and for every player.
DespawnInDayboolNight-creature flag — despawn at dawn.
EventCreatureboolMarks raid-event spawns so the event system can find its own.

Spot the detail: sleeping is lowercase (a hashed ZDOVars key) while DespawnInDay and EventCreature are capitalized — legacy raw-string keys. The atlas indexes 21 such stragglers across the game; the naming convention is the tell.

Level 3 — the code underneath

The sleep seam

Compare the RPC surface with WearNTear's six: MonsterAI registers exactly two, both in Awake, both about one thing:

RPC_Wakeup RPC_Sleep

Same ownership contract as everything else: whoever owns the creature's ZDO runs the AI and writes sleeping; any other client that needs to wake it sends the RPC. Most AI state (current target, path, timers) never syncs at all — it lives in the owner's memory and is recomputed on ownership transfer. Only the three booleans above are durable.

Harmony seam: Awake, as always — that's where both RPCs register and the synced flags are first read. Lifecycle is Awake → Start; the per-frame work rides BaseAI's update path rather than a MonsterAI Update method.
