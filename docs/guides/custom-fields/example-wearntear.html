The durability component — and the source of the famous invisible-wall trick.

Level 1 — the concept

One component carries durability for everything that breaks

WearNTear is the component that gives an object health, structural support, weathering, and damage visuals. Walls, doors, carts, beehives, portals — if a thing can crack and collapse, it has a WearNTear, and its 28 fields work identically on all of them.

That's the custom-fields payoff: learn one component's fields once, apply them to every prefab that carries it.

The invisible-wall trick, explained by three fields

The component holds a visual model for each damage state and swaps them as health drops. If a prefab's broken-state model has no visible mesh, the piece is still there — colliders and all — just unseen. That's the whole trick: it's not a hack, it's the state machine working as designed.

Three GameObject fields — m_new, m_worn, m_broken — are the damage-visual state machine. Miker's mock-your-friends build uses exactly this seam.

Level 3 — the code underneath

Six RPCs, one contract

Same ownership rule as every component: only the ZDO owner writes health. When your axe hits someone else's wall, your client sends RPC_Damage; the owner applies it, writes the new health, and RPC_HealthChanged fans the result back out. All six are registered in Awake — which is also the Harmony seam.

RPC_Damage RPC_Repair RPC_Remove RPC_HealthChanged RPC_ClearCachedSupport RPC_CreateFragments

Lifecycle: Awake (registers all six RPCs, seeds health from m_health) → Start → OnDestroy. Note the extra hook vs Fireplace: OnDestroy exists because a broken piece must clear its cached support so neighbors recalculate.
