## Root cause found and fixed

P7 compose configured the redirect queue WAL (`VALHEIM_ZDO_QUEUE_PATH`) but did
not configure `VALHEIM_ZDO_JOURNAL_PATH`. The C3 journal therefore ran in memory;
Gateway restart correctly returned zero objects because there was no journal to
replay. The compose contract now explicitly uses
`/var/lib/lumberjacks/zdo-queue/journal.jsonl` on the existing persistent mount,
separate from `redirect.wal`.

Fix commit: `ac6b195` (`Persist P7 C3 journal across Gateway restart`). The
roadmap note and generated HTML were included; `main` was pulled and pushed.

Earlier supporting fixes in the same proof chain include `3022d3b`, `796753c`,
`46a8e7b`, `1fe58a6`, `81ea8ed`, `5f63fc8`, and `fc1f2c5`.

## What remains unproven

There is no final green two-client cutover receipt yet.

- Candidate 8 passed C3, then i5's ownership-contention probe recorded the first
  expected rejection (`lease_missing`) but timed out waiting for the second
  contention response.
- Candidate 9 failed earlier at the OMEN motion-observation phase
  (`omen-c8-motion-observe-two`, `deadline_exceeded`) before the first durable C3
  mutation.

These are physical client/probe timing failures, not evidence that Gateway
journal replay is broken. They still block declaring the full cutover passed.

## Resume recipe

1. Start `comfy-lumberjacks-p7` and wait for the Valheim-ready preflight to pass.
2. Reuse the boot receipt only if its boot id still matches; otherwise run a new
   determinism proof.
3. Run a fresh candidate proof with a new run id. Do not weaken or skip the C3
   restart assertion; it now checks real durable replay.
4. Investigate the ownership-contention and OMEN motion deadlines from their
   per-client evidence before calling the cutover final.
