# M5-4 — Beachhead Map (next absorption candidates)

## Objective
A small, private, living document tracking the next 2–3 absorption candidates,
scored by the adoption doctrine: the exhausted, not the entrenched. Adoption
spreads by demonstration — know who sees the demonstration next.

## Context
Doctrine: `C:\work\comfy\docs\adoption-strategy.md` (labor asymmetry, beachheads,
the 1.0-surge timing wedge) and `personas.md` in the same directory for the
role landscape. This file contains judgments about real people — it is
PRIVATE: confirm the chosen location is git-ignored or explicitly accepted as
in-repo by Derek before writing candidate names. Default: create the template
in-repo with placeholder rows; keep the real names in a git-ignored
`plans/private/` (add to `.gitignore`).

## Steps
1. Create `plans/beachhead-map-template.md`: columns — candidate (role, guild)
   / toil they carry (what the tool relieves) / exhaustion vs. entrenchment
   read / relationship path (who introduces) / wedge (what demo would land) /
   timing note (1.0 surge relevance) / status.
2. Add scoring guidance distilled from the doctrine, as comments in the
   template: prefer people drowning in repetitive work; avoid gatekeepers
   deriving status from the bottleneck; a warm intro from an absorbed GM beats
   a cold pitch; lead with "get your hours back", never with the system.
3. Create the git-ignored `plans/private/beachhead-map.md` from the template
   with empty rows, and the `.gitignore` entry.
4. Wire into the rhythm: add "review beachhead map" as a monthly (not weekly)
   item in `docs/weekly-rhythm.md`.

## Acceptance
